# 向量数据库

向量数据库（Vector Database）专门存「向量」并支持按相似度检索：存进去的
每条记录是一个高维向量（比如 1024 个浮点数），查询时给它一个查询向量，
它返回**距离最近**的若干条——而不是传统数据库那种精确匹配。

## 为什么需要它

文本、图片经 embedding 模型编码后，语义相近的内容在向量空间里距离也近
（「怎么启动服务」和「服务起不来」字面不同，向量却很接近）。要在几十万条
向量里快速找出最近的几条，暴力两两比对太慢，向量数据库用 ANN（近似最近
邻）索引把查询做到毫秒级。

## 常见索引

- **HNSW**：分层小世界图，查询快、内存占用高，是大多数场景的默认选择；
- **IVF**：先聚类再在簇内搜索，内存友好，精度略低。

## 距离与相似度

常用 cosine 距离（1 - 余弦相似度）：距离 0 表示语义完全一致，越大越不
相关。检索结果里常见的 score = 1 - distance 就是余弦相似度，仅供参考。

## 轻量级代表

- **Chroma**：Python 生态常用，`pip install chromadb` 即用，支持持久化到
  本地目录，适合原型和中小规模（百万级以下）；
- **FAISS**：Meta 出的向量检索库，性能强，偏底层库而非数据库；
- **Milvus / Qdrant / pgvector**：面向生产部署的独立服务或 PG 扩展。
